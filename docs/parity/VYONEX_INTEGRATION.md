# VyonEx integration
Pinned commit: 4e8c8c5f683d75d83dabe4a9ca0c6ab18d8f92e1. VyonEx is the primary YouTube engine; NewPipeExtractor is the separately licensed Android fallback allowed by the user. No Rynx extraction logic is implemented.
Integration: `dependencies/vyonex-clean` is included as a Gradle composite build and `com.vyonex:vyonex:0.2.0` is substituted with the pinned checkout. `providers:vyonex` shares its public-API adapter between JVM and Android; the host uses OkHttp, a logged-out session, and a disabled/no-op VyonEx config store. Android search calls VyonEx Music search and continuation paging. Android stream resolution asks VyonEx first and falls through to the NewPipe module only on null or non-cancellation failure.

Implemented adapter surface: search result and playlist item mapping, largest valid thumbnail selection, nullable/negative duration handling, search and playlist continuation mapping, audio stream resolution, refusal forwarding, session-change forwarding, and stable failure classification. Resolved URLs and headers are short-lived; their `toString` omits sensitive values, the Android header registry is bounded and in-memory, and Media3 attaches provider headers at request time. Cancellation is rethrown and user-facing provider errors omit transport details. Android catalog track rows now start Media3 playback; the fallback uses NewPipe only when VyonEx cannot resolve the selected stream. Playlist detail browsing, downloads, and durable offline behavior remain incomplete.

Tests: JVM mapper/redaction tests and fallback-order tests pass. The shared `AudioStreamResolver`, short-lived `ResolvedAudioStream`, VyonEx-first `AudioResolutionChain`, and discovery preparation now live in `shared/playback/commonMain`; both VyonEx and the Android NewPipe fallback adapt to those contracts. Android URL-header routing and Media3 session instrumentation compile, but were not executed on a device. The final local deterministic gate passed provider/shared tests and built both Android APK variants.

2026-10-28 continuation: the opt-in live YouTube smoke test was attempted and failed before a provider response with `java.io.IOException` in the network connection path (`ConnectPlan.kt:472`, connection refused). It emitted no media URL or header. Live search/extraction and audible streaming therefore remain unverified; see `docs/parity/BLOCKERS.md`.

The signatures above were checked against the approved library's public API declarations and documentation only. No sample application queue/controller was reused and no extraction algorithm was reimplemented.
